# 数据格式、排版工具和运行步骤

## 1. 工具能力与分工

`scripts/build_workbook.py`从已经核对过的JSON生成题目PDF、答案PDF和生成记录。它处理中文字体、来源标签、正文换行、分页、空白算式、图片、规则点阵和等距数轴。

它不识别原图、不选择错题、不判断数学答案正确性、不自动去除图片上的手写。执行者先完成识别、清理、解题和核验，再交给工具排版。

复杂表格、分数竖式、特殊几何、答案绘图或精细双栏可以使用本批定制脚本。保留同一清单、对应编号、字体和检查标准，不把题目改写成工具方便生成的题型。

## 2. 运行环境

需要Python、ReportLab、Pillow。测试脚本另需pypdf。PDF渲染优先使用Poppler的`pdftoppm`。

在Codex桌面环境中，若提供“加载工作区依赖”工具，先调用它取得当前Python和原生工具位置；没有该工具时使用已安装的环境。不要把某位用户电脑上的运行时目录写进共享配置。

先确认依赖可导入：

```powershell
python -X utf8 -c "import reportlab, PIL; print('ready')"
```

若缺依赖且环境允许安装，仅安装需要的包：

```powershell
python -m pip install reportlab pillow pypdf
```

默认在Windows上尝试微软雅黑/宋体；其他环境提供支持中文的TrueType字体。需要时通过`--font`和`--bold-font`传入实际存在的路径。部分CFF类型的字体文件不适用于ReportLab的TTFont，改用兼容的TTF/TTC，不能只改文件扩展名。

字体成功注册并不保证所有特殊符号均可显示。最终页面要检查`× ÷ △ ☆ ◇`等符号。附带工具对算式里的`□`和`○`使用矢量描边，降低空白框或圆圈变成缺字块的风险。

## 3. 创建本批数据

复制 [example-questions.json](../assets/example-questions.json) 和它引用的示例图片到测试目录，可先验证工具能运行。正式任务替换为本批已核对数据，示例图片和示例答案不应残留。

JSON使用UTF-8。键名采用下面的固定英文名称；题干、答案和来源填写中文。JSON字符串内换行用`\n`，不能夹入注释、尾随逗号或Markdown围栏。

### 顶层结构

```json
{
  "title": "错题整理6",
  "questions": [
    {
      "id": "bookA-p007-q006-s04",
      "source": "材料A",
      "page": "7",
      "number": "6（4）",
      "status": "ready",
      "selection_reason": "仅第（4）小题旁有明确圈选",
      "blocks": [
        {"type": "text", "text": "2个5相乘得（       ）。"}
      ],
      "answer": ["25。"],
      "verification": "2个5相乘为5 × 5 = 25。",
      "work_space": 40
    }
  ]
}
```

上述为字段用法示例，来源页码是演示标识，不可把它当作用户新文件中的事实。

### 字段解释

| 字段 | 必需性/类型 | 怎么填写 |
|---|---|---|
| `title` | 必需，非空字符串 | 短标题，兼用作输出文件名前缀；过长标题会报错 |
| `questions` | 必需，非空数组 | 按最终题目顺序排列；题目/答案共用此顺序 |
| `id` | 必需，唯一字符串 | 包括来源、页、题/小题，避免跨教材冲突 |
| `source` | 必需，非空字符串 | 教材名称或材料代号，实际出现在PDF中 |
| `page` | 必需，字符串 | 印刷页码填`"7"`；没印刷页码填`"图片1（原页码未见）"` |
| `number` | 必需，字符串 | `"6"`或`"6（4）"`；小题使用中文括号 |
| `status` | 必需，枚举 | `ready`已核对，`needs_review`存在实质疑点 |
| `selection_reason` | 必需，非空字符串 | 明确题号、红圈、批改等本次依据；不印在题目中 |
| `blocks` | 必需，非空数组 | 按题目阅读顺序排列文字、算式和图 |
| `answer` | 生成答案且题目ready时必需 | 字符串数组，每条为一段答案；题目版不会读取它 |
| `verification` | 生成答案且题目ready时必需 | 实际核验依据，印在答案版中 |
| `work_space` | 可选，数值0–300 | 题后额外作答空白，单位pt，默认40 |
| `issue` | needs_review时必需 | 具体待确认位置与原因 |

`id`以及`source/page/number`组合都必须唯一。若要收录一个大题中的多幅图，可把它们作为同一条题记录中的多个block；如果分成小题，编号明确区分。

可以另存`source_file`、`source_region`、`figure_notes`等追溯信息；工具不会用这些附加字段自动识图或清理。别把“字段存在”当作来源已验证。

## 4. 支持的题目内容块

### 正文

```json
{"type": "text", "text": "（1）积的个位上是0：\n请按要求写出算式。"}
```

保持原题语义，按需使用显式换行。正文默认约12pt、行距约20pt。括号中的空白尽量保持整体不跨行；实际渲染后检查标点和空格。

### 算式和占位符

```json
{"type": "equation", "text": "□ ○ □ = □"}
```

`□`为方框，`○`为圆圈。题目要求学生填运算符时保留圆圈，不预写乘号或加号。普通`△ ☆ ◇`按字体显示。

单行太宽会报错，不自动缩小至难以书写。将两道独立算式拆成两个block；长推导按等号/步骤分行，保持数学意义。

### 局部图片

```json
{"type": "image", "path": "figures/bookA-p007-q008.png", "width": 305}
```

图片路径相对于`questions.json`所在目录解析，也可使用实际绝对路径。宽度单位pt，保持原比例；不要依赖启动命令所在目录。使用已裁好、已查看的局部图片。图片缺失会报错，工具不会静默略过图。

### 规则点阵

```json
{"type": "dots", "rows": 4, "cols": 3, "spacing": 18}
```

表示4行3列，共12点。只有原图确实为此排列时才使用。外围分组线、颜色分类等额外信息不受此模板支持，应保留原图或定制绘图。

### 等距数轴

```json
{"type": "number_line", "values": [0,5,10,15,20], "arcs": [[0,1],[1,2],[2,3]], "width": 440}
```

数组给出刻度标签，必须递增且间隔相等；此例每格5。`arcs`中起止是数组下标，因此最后一次是10到15。若原题每格1，应给出0、1、2……等完整数组，跳5格用下标差5。

原题让学生画跳跃时，`arcs`填空数组；原图已经印好跳跃时，准确填入。可用三项`[起点下标,终点下标,"标签"]`表示原图已有弧线文字，不能把应填答案标在题目图上。

## 5. 生成命令

以下命令中的技能路径和数据路径替换为当前实际路径；工作区依赖返回了专用Python时，用其完整路径代替`python`。

```powershell
python -X utf8 "技能目录/scripts/build_workbook.py" "本次任务/questions.json" --output-dir "本次任务/output/pdf"
```

如果指定字体：

```powershell
python -X utf8 "技能目录/scripts/build_workbook.py" "本次任务/questions.json" --output-dir "本次任务/output/pdf" --font "实际中文字体路径.ttf"
```

只要题目时加`--questions-only`。此模式不要求答案字段，`ready`表示原题与选题已核对，不声称答案已核验。

有待核对项但需要预览时加`--draft`。草稿文件名、页眉和对应题会标记待核对；不确定答案不会被排成已确认答案。

默认拒绝覆盖已有同名输出。选择新批次标题/输出目录，或在用户已授权修订该成品的情况下加`--overwrite`。模板在临时构建目录生成完整文件后才移到目标位置，减少失败留下半成品。

## 6. 输出与生成记录

默认生成：

- `标题_题目.pdf`
- `标题_答案.pdf`
- `标题_生成记录.json`

记录包含题目ID顺序、页数、字体和草稿状态。它仅证明结构检查与生成完成，不能证明答案正确或页面已被实际查看。

## 7. 渲染检查

先找到实际可用的`pdftoppm`。每个PDF使用不同输出前缀：

```powershell
pdftoppm -r 160 -png "本次任务/output/pdf/标题_题目.pdf" "本次任务/tmp/pdfs/questions"
pdftoppm -r 160 -png "本次任务/output/pdf/标题_答案.pdf" "本次任务/tmp/pdfs/answers"
```

输出目录提前创建。Windows上若工具不在PATH中，使用发现的实际exe绝对路径。其他可用PDF渲染器也可用于检查，确保渲染的是本次最新文件。

逐页打开生成图片。对多页文档可用总览定位问题，再以足够分辨率逐页查看细节；只看缩略图不足以检查小符号和计数笔画。

## 8. 常见问题与修复

| 问题 | 修复动作 |
|---|---|
| 找不到中文字体 | 指定实际中文TTF/TTC；不要退回不支持中文的默认西文字体 |
| 方框显示成黑块 | 算式用equation块；其他特殊符号检查字体或采用正确矢量图 |
| JSON无法解析 | 检查UTF-8、引号、逗号、字符串换行；移除注释和围栏 |
| 图片找不到 | 按JSON所在位置核对相对路径，复制稳定原图/裁图 |
| equation太宽 | 在完整数学语义处拆成两个块，保持可写字号 |
| 图片过高 | 使用准确局部裁剪或合理缩放，不漏掉必要条件 |
| 长题跨页、题图与题干分离 | 查看渲染；调整题块分段、留白或本批定制分页，并加续题来源标签 |
| 某页太空或太密 | 按题型调整work_space；保留合理的实际书写空间 |
| 模板不支持题型 | 采用局部定制输出，沿用来源和核验清单，不强改原题 |
| 生成记录有页数但肉眼未检查 | 继续渲染查看，不能报告已完成视觉检查 |

维护工具时可运行：

```powershell
python -X utf8 "技能目录/scripts/test_build_workbook.py"
```

这些测试检查工具行为。新题识别与数学准确性仍由本次材料核验决定。
